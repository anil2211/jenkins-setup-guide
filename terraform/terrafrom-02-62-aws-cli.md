Terraform Configuration Basics

Terraform code is written in HCL (HashiCorp Configuration Language).

Terraform Block Structure
block_type "label1" "label2" {
  argument_name = value
}
Important Terminology
Term	Explanation
Block	Main building unit (provider, resource, output)
Arguments	Inputs to a block
Attributes	Values generated by Terraform
Expressions	References, functions, variables
Supported Argument Types

String → "t2.micro"

Boolean → true / false

List → ["a", "b"]

Map → { key = "value" }

Expression → aws_instance.server.id

Resource Example (EC2 Instance – Syntax Corrected)


✅ Correct:

resource "aws_instance" "server" {
  instance_type = "t2.micro"
}
Output Block

Outputs expose Terraform-created values.

output "instance_ip" {
  value = aws_instance.server.public_ip
}

📌 Interview Tip
Outputs are used to:

Display values after apply

Pass values between modules

Integrate with CI/CD pipelines

Local Provider Example (main.tf)
sudo vim main.tf
terraform {
  required_providers {
    local = {
      source  = "hashicorp/local"
      version = "2.6.1"
    }
  }
}

provider "local" {
  # no configuration needed
}

resource "local_file" "example" {
  filename = "new.txt"
  content  = "We are learning Terraform"
}
What Happens Here?

Terraform downloads the local provider

Creates a file called new.txt

Content is managed by Terraform state

✅ Difference between Argument and Attribute

Argument

Provided by the user in Terraform configuration

Used to define desired infrastructure

Written inside resource or provider blocks

Example:

instance_type = "t2.micro"

Attribute

Generated by Terraform after resource creation

Comes from the provider (read-only)

Used for references and outputs

Example:

aws_instance.server.public_ip

👉 One-liner (Interview):
Arguments are inputs we give to Terraform, attributes are outputs Terraform gets after creating resources.

✅ Purpose of terraform init

terraform init initializes the working directory.

What it does:

Downloads required providers

Initializes backend (state storage)

Creates .terraform/ directory

Prepares Terraform to run plan/apply

👉 Interview Answer:
terraform init prepares the project by downloading providers and initializing the backend before any infrastructure changes.

✅ Why Terraform State File Is Required

The state file (terraform.tfstate) stores:

Mapping between configuration and real infrastructure

Resource IDs created in the cloud

Metadata and dependencies

Why it’s important:

Helps Terraform track existing resources

Enables incremental changes

Prevents resource duplication

Used for destroy operations

👉 Interview Answer:
Terraform needs the state file to know what infrastructure already exists and to manage updates and deletions correctly.

✅ How Terraform Knows What to Destroy

Terraform compares:

Terraform configuration

State file

Real infrastructure

During terraform destroy:

Terraform reads the state file

Identifies all managed resources

Calls provider APIs to delete them

👉 Interview Answer:
Terraform knows what to destroy by reading the state file, which contains the list of resources it previously created.

✅ What Happens If the State File Is Deleted

If the state file is deleted:

Terraform loses track of existing resources

terraform plan may try to recreate resources

terraform destroy will not work properly

Infrastructure may still exist in the cloud

Recovery options:

Import resources using terraform import

Restore state from backup

Use remote backend (S3)

👉 Interview Answer:
Without the state file, Terraform cannot manage existing infrastructure and may attempt to recreate resources.

✅ How Terraform Uses AWS Credentials

Terraform uses the AWS provider, which authenticates using:

Credential order (default):

Environment variables

AWS credentials file (~/.aws/credentials)

AWS CLI configuration

IAM role (EC2 / ECS)

After running:

aws configure

Terraform automatically picks up credentials.

👉 Interview Answer:
Terraform uses the AWS provider, which reads credentials from AWS CLI configuration, environment variables, or IAM roles.

⭐ Bonus One-Line Summary (Very Impressive in Interviews)

Terraform uses configuration as desired state, the state file as actual state, and providers to reconcile both using cloud APIs.
